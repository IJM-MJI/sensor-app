# sensor-app

콜로리메트릭 센서를 휴대폰으로 촬영해 **습도가 높은지** 판정합니다.
https://ijm-mji.github.io/sensor-app/

## 사용법

1. **Calibrate** — 반응 전 건조한 센서를 촬영합니다. 필수입니다.
2. **촬영** — 같은 센서를 노출 후 촬영합니다.

센서를 바꾸면 다시 캘리브레이션해야 합니다. 판정 근거가 **그 칩의 반응 전 색 대비
변화량**이기 때문입니다.

## 성능

**중첩 leave-one-video-out**으로 평가했습니다. 바깥 루프가 영상 하나를 빼고 채점하며,
안쪽 루프가 나머지 영상에서 임계값을 정합니다. 채점하는 쪽이 그 영상을 본 적이 없습니다.
신뢰구간은 **영상 단위 부트스트랩**입니다 (한 영상 안의 프레임은 서로 거의 중복이라
프레임 단위로 잡으면 구간이 비현실적으로 좁아집니다).

| | 균형정확도 | 95% CI | AUC |
|---|---|---|---|
| 습도 (RH 75% 이상) | **74.7%** | [61.8, 87.2] | 0.776 |

우연 수준은 50%입니다. 영상별로 편차가 큽니다:

| 영상 | 균형정확도 | | 영상 | 균형정확도 |
|---|---|---|---|---|
| `1_90_2` | 99.4% | | `1_90_6` | 83.3% |
| `1_90_4` | 98.0% | | `1_90_5` | **50.0%** |
| `1_80_2` | 96.4% | | `1_60` | **50.0%** |
| `1_90_3` | 85.8% | | `1_90_H2O_only` | 50.0% |
| `1_70_2` | 84.7% | | `1_90_H2O_only_6` | **40.0%** |
| `1_90` | 83.6% | | | |

> 이전 버전 README에 적었던 **82.2%는 낙관적이었습니다.** 그때는 미리 고른 held-out
> 4개만 채점했고, `1_90_5`는 학습에 들어가 있었습니다. 전체 영상을 돌아가며 채점하니
> `1_90_5`의 AUC가 **0.211** — 순위가 뒤집혀 있습니다.

### 색보정 ablation

| 방식 | 균형정확도 | 95% CI |
|---|---|---|
| 절대 LAB | 60.0% | [47.3, 71.8] |
| 배경(bg) 기준만 | 54.4% | [49.0, 61.3] |
| **캘리브레이션 대비만** | **74.0%** | [61.6, 85.3] |
| 둘 다 (배포본) | 74.7% | [61.8, 87.2] |

**캘리브레이션 대비가 성능의 전부입니다.** 배경 기준은 단독으로 쓰면 오히려 해롭고,
캘리브레이션에 더해도 0.7pt만 올라갑니다.

### ROI 민감도

원을 일부러 어긋나게 놓고 p 변화를 측정했습니다. 판정 밴드가 0.35~0.50이므로
|Δp| ≈ 0.15면 판정이 뒤집힙니다.

| 오차 | 최대 \|Δp\| |
|---|---|
| 중심 20px 어긋남, **두 촬영 모두 동일** | 0.027 |
| 중심 20px 어긋남, **촬영 사이 이동** | 0.105 |
| **반지름 1.15배** | **0.194** |
| **반지름 1.30배** | **0.363** |

중심 위치는 두 촬영에 같은 오차가 있으면 차분에서 상쇄되어 거의 영향이 없습니다.
**반지름이 지배적입니다** — 15% 어긋나면 판정이 바뀔 수 있습니다. 캘리브레이션 때
잡은 반지름을 판독 때도 그대로 쓰는 것이 중요합니다.

## H2는 판정하지 않습니다

같은 방식으로 H2 모델을 학습했을 때 **균형정확도 54.8%**(우연 50%)였습니다.
불꽃의 노랑→연두 변화는 눈에는 보이지만 ROI 평균색에서는 **약 0.5단위**만 움직입니다.
습도 반응이 약 7단위인 것과 비교하면 1/10 수준입니다.

이전 버전은 손으로 맞춘 규칙으로 H2를 판정했는데, **H2가 0%인 순수 습도 영상의 RH 90%
구간에서 "H₂ Detection"을 띄웠습니다.** 수소는 안전 항목이라 틀린 "검출됨"은 표시하지
않는 것보다 나쁩니다. 그래서 제거했습니다.

## 알려진 한계

- **60° 각도에서 동작하지 않습니다** (`1_60` 50%, 우연 수준). 원인 미규명입니다.
  70~90°에서는 84~99%입니다.
- 학습 데이터가 **센서 1개**에서만 나왔습니다. 다른 칩으로의 일반화는 미검증입니다.
- held-out 영상이 4개뿐이라 위 수치의 신뢰구간은 넓습니다.
- 중간 구간(RH 30~75%)은 학습 대상이 아니며 `Undecided`가 나오는 것이 정상입니다.

## 이전 버전에서 고친 것

- **ROI 원 선택**: 후보 중 가장 밝은 것 → **채도 면적이 가장 큰 것**. 밝기 기준은 회색
  책상을 챔버보다 우선해서, 판독이 빈 책상에서 이뤄지고 있었습니다.
- **Reset/Re-calibrate 후 멈춤**: 촬영 상태가 해제되지 않아 오버레이가 Retake 버튼을
  덮었습니다. 페이지를 새로고침해야 풀렸습니다.
- **판정 로직**: 손으로 맞춘 상수 → 학습된 로지스틱 회귀. 이전 규칙은 순수 습도 영상
  RH 90%에서도 `dropS_c=3.1`로 임계값 5.5에 닿지 못해 **습도를 한 번도 검출하지
  못했습니다.**

## 모델

로지스틱 회귀. 특징은 캘리브레이션 대비 델타이며, ROI 배경(`bg`) 기준으로 보정해
조명 변화를 상쇄합니다.

```
z = -1.525 + 0.531·Δflame_a - 0.722·Δflame_b + 1.443·Δdrop_a
           + 0.722·Δdrop_b + 0.321·Δtop_a + 1.246·Δtop_b
p = 1/(1+e^-z)      p≥0.50 → 높음,  p≤0.35 → 아님,  그 사이 → 판단 보류
```

`Δx = (x − bg) − (BL.x − BL.bg)`

학습·검증 코드는 이 저장소에 없습니다 (영상 70GB가 필요합니다).
