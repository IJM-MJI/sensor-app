# sensor-app

콜로리메트릭 센서를 휴대폰으로 촬영해 **습도가 높은지** 판정합니다.
https://ijm-mji.github.io/sensor-app/

## 사용법

1. **Calibrate** — 반응 전 건조한 센서를 촬영합니다. 필수입니다.
2. **촬영** — 같은 센서를 노출 후 촬영합니다.

센서를 바꾸면 다시 캘리브레이션해야 합니다. 판정 근거가 **그 칩의 반응 전 색 대비
변화량**이기 때문입니다.

## 성능

학습에 **전혀 쓰지 않은** 영상 4개로 검증했습니다. 임계값은 영상 하나를 빼고 나머지
셋에서 골라, 채점 대상 영상을 본 적이 없습니다. 우연 수준은 50%입니다.

| | 균형정확도 | AUC |
|---|---|---|
| 습도 (RH 75% 이상) | **82.2%** | 0.912 |

영상별: `1_90_2` 99%, `1_80_2` 95%, `1_70_2` 84%, **`1_60` 50%**

held-out 영상에서 실제 RH에 따른 평균 확률 — 단조 증가합니다:

| RH | 20 | 30 | 40 | 50 | 60 | 70 | 80 | 90 |
|---|---|---|---|---|---|---|---|---|
| p(높음) | .19 | .18 | .30 | .40 | .47 | .48 | .56 | .61 |

## H2는 판정하지 않습니다

같은 방식으로 H2 모델을 학습했을 때 **균형정확도 54.8%**(우연 50%)였습니다.
불꽃의 노랑→연두 변화는 눈에는 보이지만 ROI 평균색에서는 **약 0.5단위**만 움직입니다.
습도 반응이 약 7단위인 것과 비교하면 1/10 수준입니다.

이전 버전은 손으로 맞춘 규칙으로 H2를 판정했는데, **H2가 0%인 순수 습도 영상의 RH 90%
구간에서 "H₂ Detection"을 띄웠습니다.** 수소는 안전 항목이라 틀린 "검출됨"은 표시하지
않는 것보다 나쁩니다. 그래서 제거했습니다.

## 알려진 한계

- **60° 각도에서 동작하지 않습니다** (`1_60` 50%, 우연 수준). 원인 미규명입니다.
  70~90°에서는 84~99%입니다.
- 학습 데이터가 **센서 1개**에서만 나왔습니다. 다른 칩으로의 일반화는 미검증입니다.
- held-out 영상이 4개뿐이라 위 수치의 신뢰구간은 넓습니다.
- 중간 구간(RH 30~75%)은 학습 대상이 아니며 `Undecided`가 나오는 것이 정상입니다.

## 이전 버전에서 고친 것

- **ROI 원 선택**: 후보 중 가장 밝은 것 → **채도 면적이 가장 큰 것**. 밝기 기준은 회색
  책상을 챔버보다 우선해서, 판독이 빈 책상에서 이뤄지고 있었습니다.
- **Reset/Re-calibrate 후 멈춤**: 촬영 상태가 해제되지 않아 오버레이가 Retake 버튼을
  덮었습니다. 페이지를 새로고침해야 풀렸습니다.
- **판정 로직**: 손으로 맞춘 상수 → 학습된 로지스틱 회귀. 이전 규칙은 순수 습도 영상
  RH 90%에서도 `dropS_c=3.1`로 임계값 5.5에 닿지 못해 **습도를 한 번도 검출하지
  못했습니다.**

## 모델

로지스틱 회귀. 특징은 캘리브레이션 대비 델타이며, ROI 배경(`bg`) 기준으로 보정해
조명 변화를 상쇄합니다.

```
z = -1.525 + 0.531·Δflame_a - 0.722·Δflame_b + 1.443·Δdrop_a
           + 0.722·Δdrop_b + 0.321·Δtop_a + 1.246·Δtop_b
p = 1/(1+e^-z)      p≥0.50 → 높음,  p≤0.35 → 아님,  그 사이 → 판단 보류
```

`Δx = (x − bg) − (BL.x − BL.bg)`

학습·검증 코드는 이 저장소에 없습니다 (영상 70GB가 필요합니다).
